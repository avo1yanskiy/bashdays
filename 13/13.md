## Домашнее задание

* В этом уроке мы сделали с тобой сборку образов только для стейджа, адаптируй .gitlab-ci.yml так чтобы при коммите в репу master (main) собирался образ именно для прода и был с соответствующими тегами.

```
stages:
  - build

build_images:
  stage: build
  image:
    name: gcr.io/kaniko-project/executor:v1.23.2-debug
    entrypoint: [""]
  script:
    - mkdir -p /kaniko/.docker
    - echo "{\"auths\":{\"$CI_REGISTRY\":{\"username\":\"$CI_REGISTRY_USER\",\"password\":\"$CI_REGISTRY_PASSWORD\"}}}" > /kaniko/.docker/config.json
    - /kaniko/executor --cache --cache-repo $CI_REGISTRY_IMAGE --context $CI_PROJECT_DIR --dockerfile $CI_PROJECT_DIR/Dockerfile --destination $IMAGE_NAME
  tags:
    - lf-runner2

  rules:
    - if: '$CI_COMMIT_REF_NAME == "main"'
      variables:
        IMAGE_NAME: "registry.gitlab.com/avo1yanskiy/$CI_PROJECT_NAME:prod_$CI_COMMIT_SHORT_SHA"

```
* Файл .gitlab-ci.yml должен быть идентичным что в ветке master что в ветке develop, то есть они не должны вообще никак отличаться.

* Сейчас у нас задействован один раннер независимо от прода и стейджа, сделай так чтобы для стейджа запускался раннер lf-runner1, а для прода lf-runner2.

Поменял в tags: 
```
  tags:
    - lf-runner2
```

* Сделай так чтобы тег для прода и стейджа был коротким, вида dev_42b98631 / prod_42b98631, для этого используется другая системная переменная в GitLab, аналогично $CI_COMMIT_SHA.

Поменял $CI_COMMIT_SHA на  $CI_COMMIT_SHORT_SHA.
